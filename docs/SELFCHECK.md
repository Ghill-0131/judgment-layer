# 一次完整的自检

一条命令跑完所有检查。仓库里任何改动之后都该跑一遍。

```bash
python tools/selfcheck.py
```

它做八件事：

1. **协议示例自合规** — `PROTOCOL.md` 里的完整记录不光要字段齐全，还要真的过 `validate`
2. **examples 自合规** — `examples/` 下的示例同理
3. **真实数据合规** — `data/judgments.jsonl` 通过 V1-V11
4. **规则真的会拦** — 56 项规则测试，含负向（每条规则喂一个不合格样本，必须被拦住）和正向（合规写法不许误伤）
5. **编码报错是人话** — GBK / BOM / 坏 JSON 三种真文件，报错要能照着改
6. **md 里 json 能解析** — 所有 markdown 的代码块
7. **自我蒸馏反例有出处** — `data/self-distilled.jsonl` 每条都要过校验且反例带 `counterexample_ref`
8. **数字对得上** — 图上的统计和 `journal.jsonl` 现算的一致（没设 `JOURNAL` 环境变量时标 SKIP，不算通过）

第 1 和第 6 项是户部核查时补的。之前只查「能解析 + 字段齐全」，于是文档里 5 个手编的 id 和真实规则打架，一直没被发现。

**文档示例自己不合规，等于在教人写错。** 这条现在由自检强制。

---

## 为什么第 3 项最重要

校验器全部放行，等于没有校验器。

一个只会说「通过」的程序，和一个只会点头的人一样没用。

所以 `tests/test_rules.py` 里每个用例喂的都是**应该被拒绝**的东西：

- 写「暂无」当反例 → 必须拦
- 写「全部情况」当范围 → 必须拦
- 用 `conversation` 当证据 → 必须拦
- 有取代关系但没写 `relation` → 必须拦

一旦哪天有人把规则改松了，这个文件会先报错。

## 为什么第 4 项要有

配图不是插画，是论据。

图上写「N 条日志，M 条从未命中」——这些数字必须能当场重算，所以图每次生成都现读日志，不写死。

如果哪天它变成了手填的常量，那这张图就变成了装饰，装饰是可以骗人的。

所以 `tools/gen_figs.py` 每次生成都从 `journal.jsonl` 现读，`tools/reproduce.py` 能独立验证。
