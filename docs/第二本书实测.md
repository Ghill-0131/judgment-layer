# 第二本书实测：《棋王》

> 目的不是扩库，是测协议在**换作者、换文体**之后还成不成立。

## 为什么选这本

第一批 15 条判断，来源全是外国社科——《反脆弱》《穷查理宝典》《思考快与慢》《影响力》《置身事内》。

这类书有个共同点：作者在**论述**。笔记里全是可引用的论点，「不预测，改结构」直接就是一句话的判断。

如果协议只在这种书上成立，那它就是「社科普书摘录器」，不是什么通用方法。

《棋王》是对照组：

- 中国当代小说，作者阿城
- 笔记里没有论点，全是**对话原句**和读后感悟
- 8.5 万字，一个中篇加两个短篇
- 主题不是「该怎么做」，是「人怎么活着」

---

## 第一轮：能不能长出判断

9 条候选，结果 7 过 2 拦。

### 通过的 7 条

| 语句 | 来源 |
|---|---|
| 不接对方的逻辑，就没人能把你拖进他的道理里 | 感悟一，肖疙瘩 vs 李立 |
| 被抬举时，最省力的回法是问一句对方做不到的事 | 对话采样 3，王一生反问名手 |
| 反对一件抽象的事，就指一个具体位置 | 树王七，「学生，那里不是砍的地方」 |
| 被人当面顶撞，最狠的一招是请教他怎么做的 | 感悟六，「我」被王福骂后请教 |
| 想让人知道你在意，别声明，做一件事 | 感悟五，把糖推到桌子中央 |
| 认输的时候带一句硬道理，输也输得有分量 | 孩子王四，认输送字典 |
| 话说得越少，落得越重 | 感悟二，九局下完只说「和了吧」 |

### 被拦的 2 条

**C8「衣食是本，可囿在其中，终于还不太像人」**
被 V4 拦：反例写的是「暂无」。

这是全书题眼，我读的时候觉得最重要。但它是**主题句**，不是行动准则——它描述一种状态，不给动作。

**拦得对。**

**C9「何以解忧，唯有象棋」**
被 V2、V3、V4 三条同时拦：动作写不成条件句式、scope 写了「全部情况」、反例写了「无」。

这是诗，情绪价值很高，但它不是判断。

**也拦得对。**

### 第一个结论

**协议能在小说上长出判断，而且能拦住主题句和诗句。**

这说明它的分界线不是文体的分界线，是「能不能落到动作」的分界线。

小说里照样有大量可用的行动准则——它们在人物怎么接话、怎么做动作里，只是没被作者写成论点。

## 第二轮：冲突检测

把《棋王》7 条和正式库 15 条合起来，按 scope 找重叠。

结果：22 条里只有 1 对重叠，而且在「说服」场景——

```
A: 要人改变，给一个具体的人和一秒的场景，比十条数据管用。
B: 别讲道理，先找那个按下去就响的开关。
```

仔细看，它们不是冲突，是**流水线**：A 是第一步（先给具体场景），B 是 A 失败之后的第二步（再去找开关）。

### 第二个结论

**真实数据里的冲突，比想象中少。但 scope 字面重叠只能找到表面的，真正的冲突不一定共享同一个词。**

这个测法太弱，得换一个更狠的。

---

## 第三轮：故意造一对对立的判断

我造了两条**动作完全相反**的判断：

```
A: 重要的话只说一句，不加解释。
   碰到要表达一个重要的态度时，只说最关键的那一句，不补充来龙去脉。

B: 重要的话必须说透，否则一定被误解。
   碰到要表达一个重要的态度时，把来龙去脉、边界条件一次讲清楚，不留空白。
```

两条 scope 都是 `["重要表达"]`，两条反例都具体，两条置信度都是 0.7。

**两条都过 V1-V10，都进 accepted。**

### 这是真漏洞

协议现在让判断层在同一个场景里同时持有两个相反指令。

这比没有判断层更糟：

- 没有判断层，人还会自己权衡
- 有了错误的判断层，人以为已经想过了

而且这不是理论问题。真实使用里，两个人读两本书，会读到相反的答案，两条都会过闸——因为**它们各自都写得完全合规**。

---

## 补丁：V11

**规则**：同一 `scope` 下，不得有两条 `accepted` 而谁都没声明彼此关系。

声明方式二选一：

1. 取代链（`supersedes` / `superseded_by`）
2. 并立登记（`related_to` 数组点名另一条）

### 为什么这么设计

机器判断不了「动作对立」——那需要语义理解，要读得懂「只说一句」和「必须说透」是反的。

但机器判断得了「同一场景下有两条，且谁都没提对方」。

这个口径比判定对立宽，但卡在了关键处：

- 真冲突的必须显式写清，写清就不报
- 互补的也建议写一句，不写就报

**宁可多报，不能漏报。**

### 补丁的代价

加上 V11 之后，正式库立刻报出「说服」那对。

它们其实是互补的，但没写清，所以被拦。

补上 `related_to` 才放行：

```json
{"related_to": [{"id": "j-2026...", "relation": "加强", "note": "流水线第一步，对方仍不动再走另一条"}]}
```

这是对的方向：**判断之间有没有关系，不该靠读者猜。**

---

## 三件被这次实测改变的事

**一、协议从 V1-V10 变成 V1-V11。**
不是拍脑袋加的，是被自己的规则打败之后补的。

**二、`related_to` 字段进必须项。**
原协议只考虑取代链，没考虑「并存但不取代」。真实数据一跑就露了。

**三、「能不能落到动作」这个分界线，比「文体」这个分界线可靠。**
小说里的判断比社科普书里的更难找，但找出来的质量不差——因为它们是人物用身体做出来的，不是作者写在纸上的。

## 还剩什么没测

**一、第三本书，不同语言。**
目前中文书占 2 本（《人生》《棋王》），其余是译本。原文和译文的判断质量有没有差别，不知道。

**二、同一本书两个人读。**
如果有另一个人读《棋王》，他长出来的判断和我的一样吗？不知道，而且没法测——只有一个样本。

**三、判断在老去之后还对不对。**
协议说 90 天零命中就归档。但如果一条判断是对的、只是情境没再出现呢？这条损失是可接受的，但没被验证过。

**四、V11 在真实库里的误报率。**
现在库小（22 条），只报了 1 次。库大了之后会不会天天报、报得人麻木？不知道。
