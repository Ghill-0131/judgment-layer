### 刑部（审代码）—— 报 13 条

全跑了验证。最狠的一条是**我自己刚制造的回归**：

```
2 条同场景对立 -> V11 报 2 条
3 条同场景对立 -> V11 报 3 条
4 条同场景对立 -> V11 报 0 条   ← 断崖式失效
```

原因是我上一轮修「宽词误报」时用了 `SCOPE_SHARED_MAX = 3`：共用该词超过 3 条就整组跳过。

**逻辑正好反了**——条数越多越危险，却被当成越安全。

## 关键教训

**自检的第 1 项原来只查「能解析 + 字段齐全」，不跑 validate。**

于是文档里 5 个手编 id 和真实规则打架，一直没人发现。文档示例是给人抄的，抄错的代价直接落在用户身上。

现在改成：**文档里的示例必须自己先过校验，否则自检失败。**

**另一条：我为了修误报，用了一个会让真问题漏报的办法。**

`SCOPE_SHARED_MAX = 3` 是「共用超过 3 条就跳过」。看起来聪明，实际上方向反了——4 条对立的判断比 2 条危险，却被放过。

修法不是调阈值，是换个判断依据：**词本身宽不宽，不是有多少条在共用它。**
