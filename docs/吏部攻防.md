# 吏部攻防记录：协议设计漏洞

> 2026-11-08 凌晨，派子进程专门攻击协议本身。下面是它的攻击和我实地验收的结果。
>
> **规矩：反常必查。** 子进程说的我不照抄，每条都自己复跑一遍。

---

## 攻击一：hits 只看次数不看对错

**它的说法**：错判断被用了也 hit+1，越用越稳，形成正反馈。

**我核实的结果**：属实。而且协议自己就有矛盾——第 6 节说「这个信号不能伪造」，第 9 节又说「人懒得记，计数就虚」，两处自己撤销自己的主张。

**处理**：已在协议 6.1 节补 `wrong` 字段设计。还没实现，但写清了最危险的组合是「hits 高 + wrong 高」。

**没解决的**：谁判定「这次用对了」。这确实绕不开人。

---

## 攻击二：可证伪在数据模型里没有位置

**它的说法**：第 1 节说判断要过三个检验，第三个是「可证伪」，但七个必需字段里没有 falsifier/observation，V1-V11 也没有一条校验它。整份协议只有开头提过一次。

**我核实的结果**：属实。验证代码：

```
必需字段 = ['statement','action','scope','counterexample','evidence','confidence','status']
'falsifier' in 必需字段 → False
```

**后果**：三条检验里实际只有两条能被检查。而且 `evidence` 允许只有 book，书永远不产生「看到就放弃」的观察结果，所以纯 book 源的判断在结构上不可证伪，却照样能进 accepted。

**处理**：**未修。** 这条要修得加字段、加规则、动数据模型，今晚来不及。已记在待办。

---

## 攻击三：scope 身兼三职，被 V3 逼着说谎之后 V11 跟着废

**它的说法**：「报数字先查再开口」这种真通用的判断，写「全部情况」被 V3 拦，只能编个具体名目自保。编完之后 scope 既不是真边界，又是 V11 唯一的匹配键。所有人编 scope，V11 就失去分类能力。

**我核实的结果**：**方向对，但举例错了。**

它说的「子集冲突会漏报」，我实测**不漏**——我的实现按 scope 里每个元素分别分组，`["重要表达"]` 和 `["重要表达","危机沟通"]` 能正常撞上。

但它指出了真问题，只是举错了例子。我换个方向验证，立刻复现：

```
5 条互不相干的判断，都带一个宽 scope「沟通」
→ V11 报 5 条，误报率 100%
```

这才是真漏洞：**宽词共享导致满屏误报**，人报麻之后敷衍填 `related_to`，规则退化成「必须签字」。

**处理**：**已修。** 加了 `SCOPE_SHARED_MAX = 3`：

- scope 值被 3 条以上共用 → 视作宽泛标签，不据此报冲突
- 只在「专属场景」（≤3 条共用）上报

修复后验证：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 5 条共享「沟通」 | 报 5 条（误报 100%） | 报 0 条 ✓ |
| 2 条在「重要表达」对立 | 报 2 条 | 报 2 条 ✓ |
| 子集冲突 | 报 2 条 | 报 2 条 ✓ |

## 攻击四：「限定」后旧条状态没定义，三处对不上

**它的说法**：3.1 表只写「旧条 scope 收窄、superseded_by 指向新条」，没写 status 变更；附录实例却把「限定」做成了 status=superseded；6 节规则 3 只按 status 计时归档。照表实现旧条永远 accepted 永不归档，照附录实现则表是错的。

**我核实的结果**：**属实。** 查了我自己的数据：

```
旧条 status = superseded   ← 实际实现
3.1 表说的   = scope 收窄 + superseded_by 指向新条（没提 status）
```

两处不一致，照谁的都对另一半错。

**处理**：**已修。**

- 协议 3.1 表补全：「限定 = 建新条 + 旧条 scope 收窄 + 置 superseded + confidence 降一档」
- 加了 V9 强制：`凡有 superseded_by，status 必须是 superseded`
- 顺手修了它指出的另一个毛病：空库第一条判断没有关系可写却「不写关系校验不通过」，补了第四种关系 `新增`

---

## 攻击五：反例可以凭空编，V4 只剩三个黑名单词

**它的说法**：写「如果我变成一只鸟就不适用」，不含「暂无/无/同上」，过 V4。反例要挂证据，而 evidence 不用。

**我核实的结果**：**属实。**

```
反例 = '如果我变成一只鸟就不适用'
V4 拦住了吗: 没拦住
```

反例制是这协议的核心主张，结果机器门槛形同虚设。

**处理**：**修了一半，然后回退了。** 过程值得记：

1. 我加了 V12：反例必须有 `counterexample_ref`，指向 case/correction/experiment
2. 跑了一下：**15 条全挂**
3. 想清楚为什么：我那 15 条反例全是读书时**推想**的，不是真实撞上过的事
4. 硬上等于宣布「所有纯读书得来的判断都不合法」，那这个库就空了
5. 降级成 **W12 警告**：不拦，但每次 validate 都提示

这是个真实的妥协，不是偷懒。写在这里是因为下次会有人问「为什么不硬拦」。

## 攻击六：candidate 30 天计时不看人在不在用

**它的说法**：出差一个月回来，一批候选同时过期沉底。但**它自己承认**：不会丢东西，archived 可查，所以「清掉好东西」这个攻击不成立。真损失是恢复通道一年才开一次。

**我核实的结果**：同意它的自我修正。这条不严重。

**处理**：已在协议 6.2 节记录修法候选（自动归档要知道 `last_active_at`），未实现。

## 攻击七：V11 假想漏报

**它的说法**：A 的 scope 是 `["重要表达"]`、B 是 `["重要表达","危机沟通"]`，直接对立但因数组不相等而不报。

**我核实的结果**：**不属实。** 实测报 2 条，正常拦住。

这是我按「结论必须带出处、反常必查」验证后**驳回**的一条。

---

## 攻击过但站得住的（它的原话）

- 反例制作为**人的思考工具**成立，问题只在机器层没落地
- 不删本身不产生损坏，损坏来自人的注意力预算而不是存储
- 闸四不可自动化成立——「代价不可赌」这个理由找不到绕过方式
